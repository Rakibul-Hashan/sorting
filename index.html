  • v0.36 – New Insertion Sort tab (fifth tab). The key is amber and slides left while bigger numbers shift right, the sorted part is outlined in cyan, and every pass is its own block in the code box with the while checks written out. Check it: click “Insertion Sort”, press Play, then try “Sorted (best case)”. The counter says “shifts” here.
  • v0.35 – New Selection Sort tab (fourth tab). The smallest number found so far is amber, the compared number j glows, the sorted left part turns green, and each pass is its own block in the code box. Check it: click “Selection Sort”, press Play, and note that “Sorted (still O(n²))” takes just as many comparisons.
  • v0.34 – New Bubble Sort tab (third tab at the top). Each pass opens as its own block in the code box, the compared pair j and j+1 is highlighted, finished passes turn grey, and the swapped flag stops it early on sorted input. Check it: click “Bubble Sort”, press Play, then try “Sorted (best case)”.
  • v0.33 – New Quick Sort tab (top of the page, next to Merge Sort). Same layout: animated numbers with i/j pointers and a pivot, plus the code box with the pseudocode definition (QS and Partition) and the live steps. Check it: click “Quick Sort”, then press Play. “Sorted (worst case)” shows why Quick Sort can become O(n²).
  • v0.32 – Code panel now has two parts: (1) the pseudocode definition written once, (2) the steps of how it actually runs. The definition highlights the line being executed (amber) and, when a call opens, the line that called it (cyan: “MS(arr, low, mid)” or “MS(arr, mid + 1, high)”). Approach 4 adds its skip-check line.
  • v0.31 – Code panel can sit beside the animation (default on wide screens): the page widens to two columns and the code stays in view while you scroll. Buttons on the panel: “Show below / beside” and “Swap sides” (code left or right). Narrow screens keep the stacked layout.
  • v0.30 – “Code running now” panel under the animation. Each recursive call opens as its own indented copy of MS(arr, low, high) {, the highlighted line follows every step, finished calls turn grey and show where control returns, and Merge lines show real values. Works for approaches 1, 2, 4, 6, 7 and 8 in Sequential view (approach 4 also shows the skip check).
  • v0.29 – Practice: predict i, j and k. A random merge state is shown (buffer, pointers, output so far); pick the values of i, j and k after the compare-and-take code runs once. Hint ladder on wrong answers, explanation on the right one, first-try score. English/বাংলা.
  • v0.28 – Practice: fill in the missing code. The C code of approach 2 is shown with one blank (compare, loop condition, base case, middle index, buffer copy, take-left). Pick from 4 options; wrong answers get a hint and another try, the right one gets an explanation. First-try score. English/বাংলা.
  • v0.27 – Practice exercise: merge two random sorted lists yourself by clicking the next number for the output. Gentle wrong-answer feedback, a 3-step hint ladder (small hint → stronger hint → the answer), a “Copy the rest” step when one list is empty, and a mistake count. English/বাংলা.
  • v0.26 – Live variables under the step text: left, mid, right, i, j, k (as in the C code) plus the condition with real values, e.g. “3 <= 8 → true”. Hover a variable for its meaning. Shown for approaches 1–5. In approach 4 the skip-check line is highlighted too.
  • v0.25 – Code follows the animation: on the “C code” tab the line for the current step is highlighted in amber (split, base case, copy to temp/buffer, compare, take left/right, leftovers). Works for approaches 1 and 2, and for the merge lines of 3, 4 and 5.
  • v0.24 – “Code in stages” for approach 8 (advanced rotations): pivot choice, binary search, rotate, two recursive merges. All 8 approaches now have code.
  • v0.23 – “Code in stages” for approach 6 (linked list): node struct, merge by relinking, slow/fast middle finder. The link-change lines are highlighted against approach 1.
  • v0.22 – “Code in stages” for approach 7 (in-place shifts): the shift-based merge, highlighted against approach 1 (no L/R arrays, no buffer).
  • v0.21 – “Code in stages” for approach 5 (Natural Merge Sort): run-finding loop + the same merge, highlighted against approach 2. Notes that the simple code re-scans runs each pass (the animation scans once).
  • v0.20 – “Code in stages” now covers approach 3 (bottom-up) and 4 (optimized). Their changes are highlighted against approach 2 (the skip-merge check, or the iterative pass loop).
  • v0.19 – “Code in stages” panel for approaches 1 and 2: plain actions (EN/বাংলা) → pseudocode → complete runnable C code with a Copy button. For approach 2, “Highlight what changed vs approach 1” marks the key differences. Other approaches show “coming later”.
  • v0.18 – Bilingual glossary (17 terms: array, index, pointer, buffer, run, rotation, link, stable…) with small examples; Bangla terms use the “বাংলা (English)” style.
  • v0.17 – “Where do the costs come from?” panel: explains time (levels × n), the reference comparison limit, and the memory cost of the selected approach, using the current example. Also separates Θ growth from real running time.
  • v0.16 – New approach 8: Advanced in-place merge using block rotations (binary search + rotate, no extra array). Approaches 7 and 8 now sit in an optional “Advanced stage” group in the dropdown so beginners can start with 1–6.
  • v0.15 – New approach 7: Simple in-place merge using shifts. No auxiliary array; shows each shift step. New “Shifts” counter. Try Reversed input to see the Θ(n²) cost.
  • v0.14 – New approach 6: Linked-list Merge Sort. Merges by relinking nodes: 0 array writes, 0 allocations, and the leftover list is attached with one link change. New “Link changes” counter (0 for array approaches).
  • v0.13 – Prediction exercise in the comparison panel: guess which approach does fewer writes (or “Same”) before the table is revealed. Prediction mode can be switched off.
  • v0.12 – Input pattern buttons: Sorted, Reversed, Random, Duplicates, Nearly sorted (8 numbers). Click one, then watch the animation and the comparison table change.
  • v0.11 – Same-input comparison: pick any two approaches and see their operation counts side by side for the current input (fewer operations highlighted in green).
  • v0.10 – New approach 5: Natural Merge Sort. One scan finds existing sorted runs (shown as separate lists), then runs are merged pass by pass. Sorted input needs only n−1 comparisons and 0 writes.
  • v0.9 – New approach 4: Optimized recursive Merge Sort. Checks arr[mid] ≤ arr[mid+1] before each merge and skips it when already in order (counts as 1 comparison). Try a sorted input to see 0 writes.
  • v0.8 – New “Splitting view” option for recursive approaches: Concurrent (all groups at a level divide together, then merge level by level) alongside the original Sequential real-recursion order. Counts are identical in both.
  • v0.7 – New approach 3: Iterative bottom-up Merge Sort. Starts with every number as its own list, then merges pass by pass (1→2→4→8…). No splitting, no recursion (max depth 0), shares one buffer.
  • v0.6 – Step slider: drag to jump to any step directly (works with Play, ◀ ▶| and arrow keys).
  • v0.5 – Every list is now drawn as its own box (LEFT LIST / RIGHT LIST / OUTPUT). Each comparison is a separate step with a bracket joining the front of the left list to the front of the right list, then a second step takes the smaller one. Left and right items have different colours. “Why do we split?” text corrected: comparisons happen only between two different lists.

  • v0.3 – Split animation: the array now divides and drops down level by level (and rises back up when merging) instead of blurring. New sleek dark glass UI.
  • v0.2 – Approaches: basic recursive (temp arrays) and reusable auxiliary array, with operation counts.
